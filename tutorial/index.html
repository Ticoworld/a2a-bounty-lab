PONS MCP / A TESTED WALKTHROUGH

Your first paid
agent call.

Follow one real Scout request from price quote to answer and receipt. Inspect the completed run before funding your own wallet.

SDK 2.3.1Node 22Actual MCP execution

1. Install and run the free checks

From the repository root, install the tutorial’s pinned SDK version and initialize the actual MCP server. These checks discover tools and read the quote without making a payment.

Install the tutorial
npm ci --prefix tutorial
Free preflight checks
node tutorial/scout.mjs --preflight
node tutorial/mcp-smoke.mjs --readonly

The missing-wallet result during preflight is expected. It shows that the payment quote was recognized without spending. MCP is how the client calls tools; HTTP 402 is the service asking for payment.

2. Check the offer and funding

Use a separate signing wallet you control. Fund it on Robinhood Chain with the service amount in USDG and enough native ETH for gas. A balance on another chain will not pay the gas here.

Recorded Scout offer
grade_launches?n=5

The live HTTP 402 is the actual offer. Confirm its fields before a paid call; the saved run is evidence of that run’s price.

3. Call the paid tool

The helper starts the SDK’s stdio server, discovers its tools and invokes x402_fetch. This is the paid step. Enter your separate wallet key locally; the helper reads it from stdin.

Paid MCP call · PowerShell
$testSecret = Read-Host 'Separate test-wallet private key' -AsSecureString
[Net.NetworkCredential]::new('', $testSecret).Password | node tutorial/mcp-smoke.mjs --pay
$testSecret = $null

The helper saves an attempt record before requesting payment and refuses another paid run while that record exists. Its local one-cent policy settings and the full MCP requests are documented in the source walkthrough.

A timeout does not prove that no payment happened. Check the saved record and chain receipt before another attempt. Deleting an attempt file is not a substitute for reconciliation.

4. Inspect the result and receipt

The actual MCP run returned HTTP 200, five Scout launch grades and a transaction hash. A separate receipt check matched the 10,000-unit USDG transfer to the intended merchant.

Payment transaction
0xcc38e82a63e946434836f830d8f26a5e66fcec0ce4780def52dc1ac1c9c16b6a
Tool used after the paid call
pons_tx_status

This establishes the payment-to-response integration. It does not establish that Scout’s grading is useful or correct.
